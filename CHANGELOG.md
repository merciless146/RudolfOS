# Rudolf OS changes

Each version's first line after "Summary:" is what Settings shows before an update is installed; the list is what
"What's new" and the notification after an update show. The newest version comes first.

## 1.6.2 (in progress)
Summary: In progress.
- Fixed: Bring your files now opens an old Windows disk's BitLocker for real. It was checked in a virtual machine on Rudolf OS's
  own kernel with BitLocker volumes made by Windows: AES-XTS (Windows 10 and 11), AES-CBC, and AES-CBC with the older Elephant
  diffuser. Each opened read-only with its recovery key, which is stored nowhere. Two fixes: opening no longer waits for ever for
  the system's device manager, and a mistyped recovery key now says "That key does not open it." instead of "BitLocker could not
  be opened here".
- Changed: the Standard desktop is now called Chromium (it is the same desktop: the desktop page in Rudolf's Chromium), and
  Settings › System health › Desktop engine lists the three as Native, Chromium, Lite. A computer on Standard stays on it and
  shows it as Chromium; nothing saved changes. Help, System health, the self-test, the sign-in's messages and rudolf-fetch say
  Chromium too.
- Fixed: the Several monitors check failed on every run although its tests passed: monbeh_t.js named a picture
  "cmp.lock:cover2.diff.png", and GitHub's upload of the pictures refuses a ':' in a file name. Nothing in Rudolf OS changed.
- Fixed: the Lite engine check's apps' own title bars test (csd161_t.sh, 7) failed whenever it ran after 18:00 UTC: with no
  theme chosen the native desktop turns dark at night, and the window's edge is then the dark theme's, as it should be.
  The test now chooses the light theme. Nothing in Rudolf OS changed.
- Safer: no script from another site ever runs in the desktop's page or an app window, which hold the key to the system's own
  service. Lua (Command Prompt, BlockLua Builder, Blitzen) always uses Rudolf's own copy of its runtime, never one downloaded from
  a website, and the page now has a security policy that refuses any other site's script. Flash content plays in a sealed-off frame
  of its own: the Flash Player app, and Oracle's pages for Flash files.
- Fixed: closing Steam's window left Steam running out of sight (it goes to a tray icon, and Rudolf OS has no tray), using memory
  until it was force quit. When its last window is closed, and no game of it is running, Steam is now asked to quit as it quits
  itself, and ended if it has not after 30 s; signing out also asks it to quit first (docs/plan-1.6.2.md Part 14, found on the
  owner's Vivobook). Task Manager's Force quit is unchanged.
- Faster: on the native desktop a Linux app such as Steam is started as soon as Rudolf knows it, instead of after every list of
  apps (the Library's, the Linux apps', Debian's) one after another and the Start menu's pictures, which took about 10 seconds on a
  slow laptop; the list of installed Linux apps is kept and given again at once until an app is installed, updated or removed; and
  the desktop's icons and Start menu no longer wait minutes for Linux apps' pictures that cannot be had.
- New: Linux apps' progress on their taskbar buttons (docs/plan-1.6.2.md Part 25b). A Linux app with a download or other work in
  progress shows it on its taskbar button while its window is minimized (on Chromium: while another window or the desktop is in
  front), with the same fill as Rudolf's own windows and the same Display Properties › Taskbar › Progress colour, on Chromium and
  on the native desktop alike. Apps that say it with the Unity launcher signal (Chromium-based and Electron apps, and others) are
  heard by your account's own portal on your account's own session bus; Firefox's own progress on its window (the XApp hint) is
  read from the window itself. Only your own apps, and a Flatpak app only if it may talk to com.canonical.Unity and only for its
  own desktop file. A percentage only: the creeping fill stays for Rudolf's own work.
- Fixed: the Blitzen knows check's "⚡ Why?" test (bzwhy57_t.js, 4) failed at some times of day: when the search, which
  reads the log lines with their times, found two pieces of one document's section, both had the same name, and the test
  took the one kept for the one unticked. It now unticks a row by its place and looks for that row's text. Blitzen leaves
  out what is unticked, as it did; nothing in Rudolf OS changed.
- Fixed: Oracle's status line kept saying "Goes To: <address>" after the mouse left one of Oracle's own pages (its home
  page, the reader) for the rest of the desktop or Oracle's own bar: Chromium does not tell such a page that the mouse
  left it, so the desktop now ends it itself when the mouse arrives on its own page.
- New: Rudolf's title bar on the Chromium desktop's windows from outside the page (docs/plan-1.6.2.md Part 29, the owner, 2026-11-21): Linux
  apps, the encrypted Oracle and Oracle's Tor windows get the same title bar, buttons, edges and window menu as Rudolf's own windows
  (and as Native's frames), in the title-bar style and colour chosen in Display Properties. Drag the title bar to move them, any edge
  or corner to size them; maximize and restore, minimize (the taskbar button brings them back), close (the app is asked, as by its
  own close button), Always on top and the workspaces from the window's menu. A click on the desktop or another window puts the app
  behind it, its window keeping its place with the app's name ("Click to show it"). Full-screen videos and games keep the whole
  screen with no frame; dialogs open in the middle of their window. Chromium-based windows (the encrypted Oracle, Tor windows,
  Chromium-based browsers) leave their own frame off; apps that always draw their own (Steam, Discord) show both, as on Native.
- Fixed: on the Native desktop, Task Manager could come up as an empty window for several seconds (or not at all) while the desktop
  was busy, for example while Steam was starting: its page waited for the desktop's hidden background page. Task Manager now has a
  page of its own and comes up at once (docs/plan-1.6.2.md Part 14, found on the owner's Vivobook).
- New: two-player games from the Rudolf OS Library on your home network (docs/plan-1.6.2.md Part 30; Ember Reach 0.5.2's
  duels). Press Host on this network in the game, and Rudolf OS runs a small relay on this computer while you play,
  and announces it on the network; on the other computer Find games lists it, and the two games meet through it.
  Nothing goes over the internet. The relay runs as your account's own user (never as root), answers only the local
  network, and the firewall opens its port to the home network only (never on a cellular connection) and only while a
  game is hosted. It stops when the duel ends, or within a minute if no game connects.
- New: Bring your files (docs/plan-1.6.2.md Part 27). Installing Rudolf OS on a disk that holds another system now looks at it
  first, read-only: Windows (each person's Documents, Pictures, Music, Videos, Desktop and Downloads, OneDrive's folders too),
  Linux (/home and its own folder names) and macOS (said: Rudolf OS cannot read a Mac's disk, and how to copy the files on the
  Mac first), each folder with its size. Keep them (the default), choose which, or erase without keeping (said with the size
  that is lost). Kept files are copied onto a USB drive and every one is read back and checked (SHA-256) before anything is
  erased; a drive that fills up is followed by another; a copy that fails or is cancelled erases nothing, and the installer
  itself refuses the disk until the copy (or the choice to erase) is made. A BitLocker disk asks for its recovery key (it is
  opened read-only and the key is never kept); a Windows that was hibernated or not shut down fully is read read-only and
  said. After the first sign-in Rudolf OS offers to bring them in (Settings › Update and recovery › Bring in files from the
  old computer): the old Documents into Documents and so on, into your own encrypted folder, names that clash kept side by
  side, each file checked again and then by the antivirus. The copy on the drive is left as it is.

## 1.6.1 (2026-11-22, release 2026112201)
Summary: In progress.
- Fixed: on Standard, with "Keep my websites encrypted with my account" on, Oracle would not open ("Oracle needs
  Rudolf's Chromium with its shell, which this computer does not have"): the list it starts from was only made on Native.
- New: File Explorer to the desktop (docs/plan-1.6.1.md Part 28, the owner, 2026-11-21): items dragged from a File Explorer window
  (one, or several chosen with the selection box, Ctrl or Shift) and dropped on the desktop go into your Desktop folder, as a drop on
  a File Explorer window would put them there: from C: moved (copied with Ctrl), from a USB drive, the Games folder or a folder of
  this computer by File Explorer's checked transfer with its progress window (a read-only place's files copied), names that clash
  named as File Explorer names them (NAME - COPY.EXT). The icons appear where they were dropped (the first in the cell under the
  pointer, the others next to it) and keep that place. Dropped on a desktop folder's icon they go into that folder, on the Trash
  into the Trash. After Cut or Copy in File Explorer (its menu, the toolbar, Ctrl+X/C), the desktop's right-click menu has Paste
  (greyed while nothing is cut or copied), and Ctrl+V on the desktop pastes too: the icons where the menu was opened; Cut moves
  and empties the clipboard, Copy copies and keeps it. A desktop folder's menu has Paste into folder, a desktop file's Cut and
  Copy (one clipboard: Paste in File Explorer takes them). On Standard, Lite and Native alike: on Native the shell takes the
  drop from the Explorer window, whose page does the transfer, and gives the icons their places; its menus' Paste, Cut, Copy and
  Paste into folder are the page's. Fixed on Native: a click on the desktop gives it the keyboard, as on Standard (Ctrl+V,
  Delete and F2 on the desktop went to the window in front before).
- Security: Blitzen never shows or sends a private key, a token or one of this computer's secrets, whoever asks or
  however (social engineering, a page, file, mail or log that tells it to, a key split up, spelled out, encoded or in a code
  block). rudolfd hides them in what Blitzen is given and in what it writes, before any of it is shown, spoken, kept or
  copied ("[hidden: a private key]"), refuses an action that would send one even after Allow, and keeps Developer mode
  from reading key files. A password or a code is sent only after you allow it in the desktop's own prompt, which only
  your own click can answer. A program Blitzen runs sees only its own folder, with no network. Each attempt is in System
  health › Security.
- Security: code Blitzen writes can no longer act with the desktop's rights. JavaScript and Lua it writes run in a sandbox
  with no access to the desktop's page, its storage, rudolfd or the network (before, a program "checked by running it" could read
  the desktop's page and use the system's API: something Blitzen read, a web page or a file, could have made it write one). Lua
  runs on a copy of your own files: a check throws the copy away; ▶ Run asks, in the desktop's own dialog, before keeping what it
  changed, listing each file, and only in your own folder. An HTML answer's preview loads nothing from anywhere.
- Security: in Blitzen's answers, only the pages its web search read and Rudolf OS's own documents open with a click; any other
  address is shown whole and opens only after "Open this address?", which shows its site and what it would send.
- Security: what "Learn from what I do" keeps (what you did, your notes for Blitzen, the setting itself) is kept only in your
  account's own encrypted folder, only while you are signed in, never for another account; what 1.6.0 kept outside it is moved in.
  Blitzen's model engine no longer can save a conversation to the disk.
- Security: Developer mode: every command Blitzen proposes for your test computer is shown whole before it is sent, with what is
  risky in it said in plain words; one command at a time; one carrying a password, token or key is never sent. A workflow to start
  shows its file, and a pull request its whole change, before Allow.
- New: a minimized window's taskbar button shows the work it is doing: the button fills from its left edge to its right, a few
  pixels inside its edge and behind its picture and title, as a progress bar (a download, a page loading in Oracle, a copy or move
  in File Explorer, a drive's copy, Extract here, an installation or update, printing, a text message being sent, and any progress
  bar in the window). Work with no percentage creeps towards the end and completes when it is done; the fill fades away then, and
  restoring the window hides it. Green as it comes: Display Properties › Taskbar › Progress colour has Blue, Orange, Purple, Red,
  the accent colour and any colour. The same on Standard, Native and Lite.
- Fixed: Find printers finds network printers with the firewall on (found on a Vivobook: it listed none). It now asks
  the network as other computers do (multicast DNS from its own port, 5353), and the firewall lets in only those
  answers, from the local network and never on a cellular connection; nothing else is opened. Printers that answer
  only to the computer that asked are found too.
- Changed: Settings' pages are built from one list of additions each, in the same order as before, instead of a
  function wrapped up to 15 times. They look and work as they did; a section that fails no longer stops the sections
  after it from being shown (the failure is written to the console).
- For the phone build to come (2.0): the groundwork of its home screen's three panels: on a build marked as the mobile
  build, the three workspaces are panels shown full screen, switched with a swipe to the left or right on the desktop or
  a title bar, on Standard and Native alike. Nothing changes on computers.
- Printing: a print queue for the whole computer. Linux apps print too (LibreOffice, GTK and Qt apps, lp in Debian and
  Flatpak apps: through the queue, as on any Linux), and Settings › Devices › Print queue shows what is printing, with
  Cancel for your own documents; another account's are listed without their names and cannot be cancelled by you.
  Printers that take only pictures of the pages get them from the queue too. USB printers' devices belong to the queue
  alone, and an IPP over USB printer can be reached only through it.
- Native: an app's window loads the desktop page without 11 modules no app of its own uses (WordPro's additions, Notey for
  the office apps, the Wi-Fi panel, the computer check, the SNES core's loader, the weather, Settings' search and a few
  more); each is read the moment something of it is needed. Settings, Task Manager, Oracle, the App Store, Blitzen and
  the games and office apps that use them keep the whole page, as Standard and Lite do. Measured: no difference in memory
  that can be told from the noise (about 1 MB at most).
- Native: each app's window uses about 10 MB less memory. A window no longer makes the pictures of the start menu, the
  desktop's icons and the taskbar for itself (the native desktop draws those), nor the taskbar's pinned buttons or the
  dynamic background's moving parts under the app, and it no longer gives the desktop its list of apps again when it opens
  if the list is unchanged. On the test computer, five app windows and the hidden page: 483 MB instead of 531 MB.
- Native: the window's menu of an app that draws its own title bar says whether it can use Rudolf's instead. For apps
  whose own bar holds only the title and the three buttons, "Title bar: Rudolf's" cuts their own bar away and frames them
  as any other window, remembered for each account and app; for others the menu says Rudolf's would hide their menus and
  buttons.
- Native: one title bar for apps that draw their own. Discord, Steam, Claude, VS Code and other Electron and Chromium apps,
  and GTK 3 and 4 apps with a header bar, no longer get Rudolf's title bar above their own: their window keeps Rudolf's edge,
  round corners and resize edges, and their own bar does the rest, as on Standard. Moving them by their bar, resizing them
  from any edge or corner, their maximize, restore and minimize buttons, a double-click on their bar, the keyboard's Move
  and Size from their window menu, and a right-click on a GTK header bar (the window's menu) all work, with the same limits
  and transitions as Rudolf's own title bar. GTK's invisible shadow margins are cut away. Every other window keeps Rudolf's
  title bar as before.
- New (docs/plan-1.6.1.md Part 19): game mode does more, on Standard and Native alike. While a game is full screen the
  processor is asked for its full speed (AMD's amd_pstate and Intel's intel_pstate; not with battery saver), and behind a
  Linux game the desktop's own work waits (its processor time lowered, its animations stopped); notifications are held and
  one says how many came after, as before. Everything goes back as it was when the game leaves full screen or ends, a crash
  included. Games that ask for Feral's GameMode (gamemoderun, Steam's launch option, Flatpak games through the portal) get
  the processor's speed, and nothing else. Settings › System health › Memory › Game mode turns it all off and on.
- Apps that can use the system's title bar are asked to, once: the first time Rudolf OS starts Chromium, Brave, Edge, Vivaldi,
  Chrome or ungoogled Chromium from Flathub, Debian's Chromium, VS Code or VSCodium, it turns on their "use the system title
  bar" setting, so they get Rudolf's title bar with nothing lost. Only when you have not chosen otherwise in the app; your
  other settings are kept.
- Native: idle windows give their memory back. Notepad or File Explorer minimized, or hidden behind another window, for a
  while (Settings › System › Idle windows: on by default on computers with under 6 GB of memory, after 10 minutes) is closed
  behind the scenes and comes back where it was when you show it: its files, tabs, folder, the scroll and the window's size
  and place. Never with unsaved changes, a dialog, sound or video playing, a call, a download or a transfer; Oracle and Linux,
  Debian, Flatpak and Wine apps are never touched. Task Manager shows such a window as "Resting (no memory used)".
- New: Oracle blocks ads and trackers. A shield 🛡 in the address box says how many were blocked on the page; its menu
  turns blocking off (or on) for that site and can note a broken site in System health. Settings › Privacy › Ads and
  trackers in Oracle: on (the default) or off, the sites it is off for, and sites of your own to block. Private and Tor
  windows always block. It uses Rudolf OS's own list of well-known ad and tracking services, checked on this computer:
  nothing about the pages you visit is sent anywhere. On Standard, Native and Lite.
- The desktop page is 870 KB smaller: the Quake engine and the Galaxy Map's universe are files of their own, read only when
  Quake or the Galaxy Map opens (every window of the native desktop, and Standard's page, parsed them before). Each window
  of the native desktop uses about 5 MB less memory.
- Native: the shell's hidden pages are one. The desktop's service page, the portal's page (a Linux or Flatpak app's
  questions, file dialogs and links) and the start-up page (the notice after an update) were three pages each loading the
  whole desktop; now one page does what each did. The quick settings' switches, Do not disturb and Clear all, pinning,
  muting from the taskbar, the desktop's menus, renaming, dropping onto the Trash, files dropped from Linux apps and the
  start menu's search are done by that page at once, instead of a page of the whole desktop loaded for each. Less memory
  (on the test computer 110 MB instead of 170 MB with no window open, and no 100 MB peak for each switch).
- Security: signing in and out with your files on the disk (the encrypted folder opened with your key, your Oracle
  folder, Linux apps' folders, your account's own Linux user's session) and opening the encrypted folder of
  Settings › Security (and preparing the drive for it) are done by the drives helper as root, no longer
  by rudolfd, which reads every request of the desktop: the key goes to it on a pipe, never as an argument, and the
  account is checked again there (a removed account is refused). Nothing changes on screen.
- Security: the accounts' own Linux users (made and removed with the accounts, written into the system's user list,
  their folders given to them) and Settings › Privacy › Saved passwords for apps are handled by a helper of their
  own, no longer by rudolfd; it is asked only when an account comes or goes. Nothing changes on screen.
- Security: restart, shut down, sleep, the power settings, brightness, Task Manager's "Clear cache" and the desktop's
  priority, and setting the clock are done by a power helper of its own, no longer by rudolfd. Nothing changes on screen.
- Security: Wi-Fi (scan, join, forget, the radios and bands, the country, the adapter), an address by DHCP or a fixed
  one and the name server, the firewall, the hotspot and metered connections are handled by a network helper of its
  own, no longer by rudolfd; a network's password reaches it on its standard input only. Nothing changes on screen.
- Security: Bluetooth (turning it on and off, searching, pairing, connecting, forgetting, the pairing question) and
  Thunderbolt and USB4 devices (approving, not approving, forgetting) are handled by a devices helper of its own, no
  longer by rudolfd. Nothing changes on screen.
- Security: Task Manager's End process and End process tree, and reading the kernel's messages (System health, the
  crashes list), are handled by two small helpers of their own, no longer by rudolfd. Nothing changes on screen.
- Security: the display's settings (the graphics path, the desktop's shell, resolution and frame rate, the keyboard's
  layout, restarting the display or the desktop's browser) and sound (the volume, the microphone, the echo canceller,
  the sound card) are handled by helpers of their own, no longer by rudolfd. Nothing changes on screen.
- Security: rudolfd can be confined (off by default until a beta has run with it: /persist/etc/rudolf-confine, or
  rudolf.confine= at the start-up, off, log or on). All of rudolfd loses the system calls and capabilities nothing it
  starts needs; each request that starts no program is put in a narrow confinement of its own (only rudolfd's own
  system calls, writing only in rudolfd's folders through Landlock, which the kernel now has, fewer capabilities);
  each of rudolf-rootd's helpers gets only its own capabilities; and the API answers each window only what its code
  asks for (the native shell, the page). Refusals are said in System health.
- New: a ZIP larger than 1.5 MB in Downloads (kept on the disk) opens in Archive Manager, which lists what is inside it
  (names, sizes, folders; the first 3,000 shown) without loading it, with Extract here; File Explorer's Open with offers
  Archive Manager for it too. Extract here (there, or in File Explorer) unpacks it next to the ZIP with a progress window
  (the file, n of N, the bytes, Cancel): a folder named after the ZIP, its sub-folders as in the ZIP, each file kept on the
  disk and checked by the antivirus (one quarantined or blocked is said so). The ZIP is unpacked as the desktop user, never
  as root; one with entries that point outside it ("..", an absolute path) is refused, and links in it are left out.
- Changed: files kept on the disk can now be in sub-folders of Downloads, where they stay (before, they were moved back to
  the top of Downloads); only those at the top are renamed on the disk when renamed. Deleting them, the Trash and
  Downloads' own files work as before.
- New: reader mode in Oracle. On a page with an article (a news story, a blog post, a recipe) a 📖 button shows in the
  address box; it, F9 (also inside a website) or ☰ › Reader mode shows the article alone: its title, author and text, its
  pictures and links, in Rudolf's reading style, with A− A+, the width, the font (serif, sans, OpenDyslexic), light, sepia
  or dark (dark with Rudolf's dark theme), 🔊 Read aloud in Rudolf's own voice (the sentence being read highlighted) and
  🖨 Print (the article alone). ✕ Exit reader or F9 gives the page back as it was. Nothing of the website runs in reader
  mode. Also for .HTM files on C:. On Standard, Native and Lite. It uses Mozilla's Readability (Apache License 2.0).
- Fixed: the release build no longer stops when linux-firmware updates a file: it takes linux-firmware at the commit the firmware list was made from (the list's new "R" line), and a check runs that fetch on every change to the list.
- Changed: Oracle › ☰ › Reopen my tabs next time now brings back every Oracle window you had, the tabs asleep (💤, loaded
  when clicked) except the one in front, so Oracle starts quickly. After Oracle or the desktop ended unexpectedly, the next
  Oracle window offers "Restore your tabs?" once, even with the setting off. Your tabs are kept in your own encrypted home
  folder (locked when you sign out), no longer in the desktop's settings. Never for private or Tor windows, or Guest.
- Changed: Native uses less memory: each window's page frees its caches and collects garbage sooner (a limit that
  follows the computer's memory, checked every 5 s instead of 15), and the pages the desktop opens by itself at
  start-up wait until the others have started, so their memory peaks no longer come all at once.
- Fixed: Emu's "Open a file…" refused a ZIP or disc over 512 MB ("copy it in Files instead"). A ZIP or a disc image
  (.chd, .cdi, .gdi, .cue, .pbp, N64) chosen there is now added to the game library (a ZIP is unpacked) and the game
  added starts; nothing that large is read into the page. A 7-Zip file is refused with a reason.
- Changed: the most a "choose a file" window takes into an app at once follows the computer's memory: about a sixth
  of it (no more than 40% of what is free at that moment, and never over 2 GB) instead of 512 MB for every computer. The
  Vivobook (3.3 GB) keeps about 512 MB; 8 GB about 1.2 GB; 16 GB and more 2 GB. The message says why a file is too large.
- New: File Explorer moves files by dragging them from one window to another, between Rudolf OS's own folders, a
  plugged-in drive and the Games (Emu library) folder, either way: dropped on a window's list they go into the folder it
  shows, dropped on a folder into that folder, and what will take them is highlighted. A drag moves; Ctrl+drag copies
  (the pointer shows which). Cut, Copy and Paste in the right-click menu work the same between windows and drives. A
  move between Rudolf OS and a drive is a copy that is checked first; the originals go only once everything arrived, and
  one that is cancelled or fails leaves them where they were.
- New: a selection box in File Explorer: press on an empty spot of the list and drag over the files to select them
  (Ctrl or Shift adds to what is selected); then drag them, or right-click them. A drive's files can now be selected
  with Shift+click too, and have a right-click menu (Cut, Copy, Paste, Delete, Copy into Rudolf OS, Properties).
- New: a window shows a transfer's progress: the file, how many of how many, the bytes, the time left, and Cancel. It
  closes by itself when done and stays to say what went wrong if something did.
- Fixed: copying a large download kept on the disk (Copy and Paste in Downloads) made a 99-byte "- COPY" that did not
  open. The copy is now a file of its own on the disk; copies made like that before are mended when Downloads is opened
  (kept, never deleted).
- Fixed: File Explorer's Properties window showed only an icon.
- New: Oracle's status line (bottom left, where it says "Done") shows where a link goes while the mouse is over it:
  "Goes To: <address>". It covers links, image-map areas, a form's submit button and links in ads and other frames, on
  websites and Oracle's own pages; then the status line goes back to what it said. On Standard, Native and Lite.
- New: find in page in Oracle. Ctrl+F (or F3, Ctrl+G, or ☰ › Find in page…) opens a bar under the bookmarks bar: type
  and the matches are highlighted, "3 of 17" says where you are, Enter (or ▼, F3) goes to the next and Shift+Enter (or ▲,
  Shift+F3) to the previous one, round at the ends; Match case; Escape or ✕ closes it. Ctrl+F inside a website opens
  Oracle's bar, as in Chrome, even on sites that use Ctrl+F themselves. Text selected on the page fills the box, and the
  bar belongs to its tab. On websites, Oracle's own pages and files, on Standard, Native and Lite.
- Fixed: after a click into a website in Oracle, Ctrl+F and Ctrl+L gave the bar or the address box the look of having the
  keyboard while what was typed still went to the website.
- New: Oracle's Downloads page shows a progress bar for a file that is arriving (how much so far and how fast, and with
  a known size the percentage and the time left) and one being checked. Each download has Remove beside Open: a file in
  Downloads goes to the Trash with it; otherwise the notification "File removed from list: Not in Downloads. Ask Blitzen
  if you need help finding this file." has a "⚡ Ask Blitzen" button. Blitzen reads the download's record, the Trash and
  where files of that name are, and says whether the file was moved, put in the Trash, deleted or never downloaded.
- New: reopen a closed tab in Oracle. Ctrl+Shift+T (also inside a website) or ☰ › Reopen closed tab brings back the last
  tab you closed, at its place and with its back and forward pages; again, the one before. ☰ › Recently closed… lists the
  last 25; a closed window is one entry that brings its tabs back in a window of their own. The list is kept in memory
  only, never written anywhere: it is forgotten when Oracle's last window closes and when you sign out. Private and Tor
  windows keep their own list, which goes with the window. On Standard, Native and Lite.
- Fixed: Make a Rudolf OS USB stick on an older Rudolf OS stick said "/dev/sdb is in use (mounted at
  /run/rudolf/stkinfo-sdb/i). Unmount it first." Settings' look at what such a stick holds left its image mounted
  when the stick had no third partition. It now always unmounts, never looks while a stick is being made, and Make the
  stick unmounts a look left behind by 1.6.0.

- New: Rudolf OS moves to its new desktop host by itself once, shortly after starting (a few seconds; your files, ROMs, game saves and settings move along). If it cannot start, the desktop runs as before. Settings > Oracle sign-in > Real browser tabs turns it off.
- New: downloads from websites go to C:\DOWNLOADS through the firewall, file-type and antivirus checks, also files that need you to be signed in.
- New: a website or a video can go fullscreen; Esc brings it back. Games can capture the mouse pointer.
- Fixed: Ctrl+W, Ctrl+Q, Ctrl+T and Ctrl+N could close or quit the desktop or open a browser window over it. Ctrl+W now closes an Oracle tab, Ctrl+T opens one, and Ctrl+Q does nothing harmful. Linux apps get these keys unchanged.
- New: Task Manager: Processes (every process grouped by what it is, with CPU and memory, and End process), Performance (CPU, memory and network), System (Rudolf OS, the desktop's host, the services with Restart, the kernel, its drivers and warnings), Hardware (processor, graphics, display, storage, network adapters, sound, input devices, battery). Apps lists Oracle's real tabs with the memory each page uses.
- New: Report a problem (Task Manager, or Start): opens a ready-filled report on the Rudolf OS issue tracker on GitHub, with the state of the computer at that moment. It leaves out your name, files, web and network addresses and Wi-Fi names; you review it before sending, or save it to send later.
- Security: ending a system process or restarting a service asks for an administrator's password; the processes Rudolf OS needs cannot be ended. Websites in Oracle keep their own protection against being shown inside other pages.
- Fixed: with the newer Chromium that security updates bring, Rudolf OS's browser settings were not applied, so the system's own file dialog (which froze some PCs) could open again, and real tabs could not start. Both work again.
- Known limits: a few websites forbid the script that makes fullscreen work and stay in their window; downloads are limited to 1.5 MB as before.
